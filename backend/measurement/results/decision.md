## 4. Cost of Intelligence -- compression + caching (Phase C, added post-CP1)

Generated by `python -m backend.measurement.run_cost_of_intelligence`, run
against the same 28-query gold set as section 1, with zero Snowflake
credentials -- retrieval, compression scoring, and cache key/TTL logic are
all real, unmocked code (`backend/app/llm/compress.py`,
`backend/app/llm/cache.py`, `backend/snowflake/llm.py`'s
`CortexLLMClient.chat()`); only the Cortex COMPLETE transport call
(`CortexLLMClient._call_complete`) is stubbed to a deterministic response,
since no live account is available in this sandbox. Every number below is
copy-pasted from the script's actual stdout, not estimated.

Exact command and full output (re-run 2026-08-07 after Phase E model
routing landed -- `estimated_cost_saved_usd` below differs from this
section's original number because `measure_cache()` runs `hyde` calls

**Token-reduction %:** 34.71% -- weighted across all 280 paper abstracts
(28 gold-set queries x top-10 retrieved papers each) compressed from
top-N=4 extractive sentence selection, 64,947 estimated tokens before ->
42,401 after (`backend/app/llm/tokenizer.py`'s `estimate_tokens`).

**Cache hit-rate %:** 50% -- each of the 28 gold-set queries' `hyde` call
was issued twice through the real `CortexLLMClient.chat()` -> `TTLPromptCache`
path (simulating a same-session repeat, e.g. pagination or a retry): 28
misses (first issue) + 28 hits (repeat issue) = 56 calls, 28/56 = 0.5. This
is a synthetic *2-calls-per-query* traffic pattern chosen to exercise the
real cache mechanics end-to-end without a live account, not a claim about
production hit-rate under organic multi-user traffic -- a human with
credentials should re-run this with `NEULIT_PROFILE=live_no_memory` against
real session traffic (see section 2) to get an organic number.

**Estimated cost-reduction %:** 13.88% -- compression-only, computed on a
representative 1000-prompt-token/300-completion-token `summary`-shaped call
using the real `compute_cost_usd()` function against the same published
`claude-3-5-sonnet` pricing row researched for `Handoff-Log.md` item 4
(1.8 credits/Mtok in, 9.0 credits/Mtok out, $2/credit): baseline
$0.009000 -> $0.007750. This number is compression's contribution only, on
one representative call shape; it is additive with (but not summed into)
the separate `hyde` cache savings reported above
(`estimated_cost_saved_usd=$0.00336` for this synthetic run, now priced at
the cheap-tier `mistral-7b` rate per Phase E routing -- see section 5),
since caching and compression act on different call sites
(`hyde`/`relevance_check` vs `summary`/`citation_check`).

**What this does NOT show:** a live Snowflake account's real credit
consumption, or an organic (non-synthetic) cache hit-rate from actual
multi-user /query traffic. Both require the same live-account re-run
already called for in section 2 above.

Raw JSON: `backend/measurement/results/cost_of_intelligence.json`.

## 5. Call-site model routing (Phase E, added post-section-4)

Generated by the same `python -m backend.measurement.run_cost_of_intelligence`
run as section 4 (see its full output above) -- `measure_routing()` in
`backend/measurement/run_cost_of_intelligence.py`. Compares the real,
unmocked `model_for_call_site()` (`backend/app/llm/routing.py`) resolution
for the `hyde` call site with routing off (`SNOWFLAKE_CORTEX_MODEL=
claude-3-5-sonnet`, the pre-Phase-E single-model config) vs routing on (no
env vars set, hardcoded cheap-tier default `mistral-7b` applies), over the
same 56-call volume (28 gold-set queries x 2 issues/query) `measure_cache()`
in section 4 already executes, at that measurement's per-call token shape
(120 prompt / 40 completion tokens, from `_stub_complete_response`), priced
via the real `compute_cost_usd()` against both `MODEL_PRICING` rows in this
script's `_PRICING` dict.

**Result:** routing off costs $0.064512 for 56 `hyde` calls
(claude-3-5-sonnet @ 1.8/9.0 credits per Mtok in/out, $2/credit); routing on
costs $0.006720 (mistral-7b @ 0.2/0.9 credits per Mtok in/out, placeholder
rate -- see `snowflake/sql/02_tables.sql` comment). **Delta: $0.057792
saved, an 89.58% reduction**, on this call volume and token shape.

**Caveat, stated plainly:** the *percentage* reduction is a real
computation from real code (`model_for_call_site` + `compute_cost_usd`,
both exercised exactly as production would call them). The *absolute
dollar* accuracy is bounded by `mistral-7b`'s placeholder pricing row --
no researched, cited per-token rate for this model was found in this pass
(unlike `claude-3-5-sonnet`/`claude-sonnet-4-5`, which cite finout.io). A
human with real Snowflake credentials must reconcile this rate against
`SNOWFLAKE.ACCOUNT_USAGE` before this $ delta (or `/economics` numbers that
include cheap-tier calls) is trusted for a real cost claim. This is the
same reconciliation already flagged for the other two pricing rows in
`Decisions.md`.

**Scope:** this only measures the `hyde` call site (one of two cheap-tier
sites; `relevance_check` would show the same relative delta since both
route to the same cheap-tier model). It does not include the strong-tier
call sites (`summary`/`citation_check`/`refine`/`memory_distill`), which
are unaffected by Phase E when no `SNOWFLAKE_CORTEX_MODEL_STRONG` override
is set (they already defaulted to `claude-3-5-sonnet` pre-Phase-E and still
do) -- routing is a no-op cost-wise for those four sites out of the box.
